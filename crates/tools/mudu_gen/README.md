# mudu_gen

`mudu_gen` is the code generation crate for MuduDB. Its CLI binary is `mgen`.

`mgen` generates source code from:

- DDL SQL files, for entity/table model code
- WIT files, for message types used in serialization and deserialization

## Install

```bash
cargo install --path ./mudu_gen
```

After installation, the executable name is:

```bash
mgen
```

## Supported Languages

- `rust`
- `csharp`
- `assemblyscript`
- `python`

## Command Overview

```bash
mgen [OPTIONS] [COMMAND]
```

Global options:

- `-v`, `--verbose`: enable verbose output
- `-h`, `--help`: print help
- `-V`, `--version`: print version

Subcommands:

- `entity`: generate entity source files from DDL SQL
- `message`: generate message source files from WIT
- `check-sql`: statically check SQL string literals in guest sources against the DDL schema

## `entity`

Generate entity code from one or more DDL SQL files.

```bash
mgen entity \
  --input-source-files <FILE>... \
  --output-source-folder <FOLDER> \
  --type-desc <FILE> \
  --lang <LANG>
```

Arguments:

- `-i`, `--input-source-files <FILE>...`: one or more input DDL SQL files
- `-o`, `--output-source-folder <FOLDER>`: output directory for generated source files
- `-t`, `--type-desc <FILE>`: output JSON file for generated type descriptions
- `-l`, `--lang <LANG>`: target language, currently only `rust`

Behavior:

- Creates the output directory if it does not exist
- Generates one source file per parsed table/entity
- Writes a type description JSON file to the `--type-desc` path
- Uses the target language file extension: `.rs` for Rust

Example:

```bash
mgen entity \
  -i ./mudu_gen/tool/test_data/sql/ddl.sql ./mudu_gen/tool/test_data/sql/type.sql \
  -o ./tmp/generated \
  -t ./tmp/types.desc.json \
  -l rust
```

## `message`

Generate message type code from WIT definitions.

```bash
mgen message \
  --input-wit-file <FILE> \
  --output-source-file <FILE> \
  --lang <LANG> \
  [--namespace <NAME>] \
  [--with-func-codec]
```

Arguments:

- `-i`, `--input-wit-file <FILE>`: input WIT file or a directory containing `.wit` files
- `-o`, `--output-source-file <FILE>`: output file path, or output directory when the input is a directory
- `-l`, `--lang <LANG>`: target language: `rust`, `csharp`, `assemblyscript`, or `python`
- `-n`, `--namespace <NAME>`: optional namespace override
- `--with-func-codec`: also generate MSSP v1 syscall frame codecs (message
  kinds, 16-byte header helpers, and per-function request/result stubs) for
  WIT `func` items; the `MessageKind` discriminant of each function is its
  1-based declaration order in the interface

Behavior:

- Accepts either a single `.wit` file or a directory of `.wit` files
- In single-file mode, writes exactly one output file to the given path
- In directory mode, generates one file per `.wit` file into the output directory
- Creates the output directory, or the parent directory of the output file, if needed
- Formats Rust output with `rustfmt` through the embedded formatter
- If `--namespace` is not provided, the namespace is inferred from the WIT interface name
- Generated files carry a `// Generated by mudu_gen. Do not edit manually.` header

Examples:

Generate one Rust file from one WIT file:

```bash
mgen message \
  -i ./mudu_gen/tool/test_data/wit/uni-command-argv.wit \
  -o ./tmp/uni_command_argv.rs \
  -l rust
```

Generate the MSSP syscall codec (message types plus frame/func codecs) for
Rust from the canonical WIT directory:

```bash
mgen message \
  -i ./crates/common/mudu_binding/wit \
  -o ./tmp/universal \
  -l rust \
  --with-func-codec
```

Generate C# files from a folder of WIT files:

```bash
mgen message \
  -i ./mudu_gen/tool/test_data/wit-schema \
  -o ./tmp/wit_out \
  -l csharp \
  -n Demo.Messages
```

## `check-sql`

Statically check SQL string literals in guest source files against the DDL
schema. See `doc/dev/sql_subset.md` for the supported SQL subset, the
diagnostic severity model, and the extraction rules.

```bash
mgen check-sql \
  --lang <LANG> \
  --ddl <FILE>... \
  --input <PATH>
```

Arguments:

- `-l`, `--lang <LANG>`: source language: `rust`, `as`, or `cs`
- `-d`, `--ddl <FILE>...`: one or more DDL SQL files whose `CREATE TABLE`
  statements define the schema; same-named tables across files get the
  union of their columns (for deployment variants such as partitioned
  schemas)
- `-i`, `--input <PATH>`: a source file, or a directory scanned recursively
  for the language's extension (`.rs` / `.ts` / `.cs`)

Behavior:

- Extracts every string literal whose content starts a DML statement
  (`SELECT` / `INSERT INTO` / `UPDATE .. SET` / `DELETE FROM`,
  case-insensitive) and checks it against the schema: syntax, table and
  column existence
- Reports diagnostics as `file:line:col: severity: message`
- `error` diagnostics (unknown table/column, syntax errors, bind-parameter
  arity mismatches, `SELECT` result-shape mismatches against turbofish
  entities) make the command exit with code 1
- `uncovered` diagnostics (valid SQL beyond the supported subset, e.g.
  `JOIN`) never fail the build and are only printed with `-v`

Examples:

```bash
mgen check-sql -l rust -d ./sql/ddl.sql -i ./src/rust
mgen check-sql -l as -d ./sql/ddl.sql -i ./assembly
mgen check-sql -l cs -d ./sql/ddl.sql -i ./src
```

## Notes

- The package name is `mudu_gen`, but the installed CLI binary is `mgen`.
- `message` also has the alias `msg`.
- The current implementation for `entity` is based on DDL SQL parsing.
