# Regenerating the MSSP syscall codec

The per-func syscall codec (`src/mudu_sys/generated/uni_syscall.rs`) and most
universal DTOs (`src/universal/uni_*.rs`) are produced by `mudu_gen` (`mgen`)
from the WIT contracts in `crates/common/mudu_binding/wit` — the same WIT and
the same generator the host-side `mudu_binding` codec uses, so guest and host
stay byte-compatible by construction. Do not edit the generated files
manually; they carry the `// Generated by mudu_gen. Do not edit manually.`
header.

The wire format is the MSSP v1 in-place revision: request/record bodies are
MessagePack maps keyed by 1-based parameter/field numbers (lenient decode:
unknown keys skipped, missing fields defaulted, any integer width accepted);
result envelopes stay `[0u8, value]` / `[1u8, UniError]`; variants stay
`[tag, payload]`. All body values go through the hand-written `mp_wire`
runtime (`src/universal/mp_wire.rs`), mirrored automatically from
`mudu_binding` by `mudu_api_sync` together with the rest of `src/universal/`
(including `uni_serde.rs`, the legacy JSON serde shim, and
`uni_schema_desc.rs`).

## Command

From `crates/tools`:

```sh
cargo run -p mudu_gen -- message \
    -i ../common/mudu_binding/wit \
    -o <scratch dir> \
    -l rust --with-func-codec
```

The generator also accepts `-t/--type-desc <path>` to emit the
`UniSchemaDesc` schema descriptor JSON; the descriptor is only checked in on
the host side (`mudu_binding/src/codec/syscall_payload/syscall_schema.desc.json`,
see the host `REGENERATE.md`). This crate consumes only the mirrored
`UniSchemaDesc` type in `universal/uni_schema_desc.rs`, not the JSON itself.

## Where the output lands

| Generated file (`<scratch dir>/`) | Copied to (`crates/sdk/mudu_api/rust/src/`) |
| --- | --- |
| `uni_syscall.rs` | `mudu_sys/generated/uni_syscall.rs` |
| `uni_<name>.rs` (most types) | `universal/uni_<name>.rs` (same name) |
| `uni_command_result.rs` | `universal/uni_command_result.rs` (also contains `UniCommandReturn`) |
| `uni_query_result.rs` | `universal/uni_query_result.rs` (also contains `UniQueryReturn`) |
| `uni_message.rs` | **not imported** — no guest-side consumer today |

After copying, run `cargo fmt` in this crate (the raw generator output is not
rustfmt-clean; the checked-in copies are).

Compatibility shims kept for the pre-generation module paths (do not delete):

- `universal/uni_command_return.rs` re-exports `UniCommandResult` /
  `UniCommandReturn` from `uni_command_result`.
- `universal/uni_query_return.rs` re-exports `UniQueryReturn` from
  `uni_query_result`.

Hand-written universal modules with no WIT counterpart (left untouched by
regeneration): `uni_def`, `uni_get_argv`, `uni_get_result`, `uni_key_value`,
`uni_put_argv`, `uni_put_result`, `uni_range_argv`, `uni_range_result`,
`uni_relation`, `uni_result`, `uni_session_open_argv`, `uni_type_desc`.

Everything else around the generated code is glue: `mudu_sys/payload.rs`
(transport-error adapter + raw kind constants for the mock router and tests)
and the per-kind modules under `mudu_sys/` (public `serialize_*` /
`deserialize_*_result` API, `UniCommandReturn`/`UniQueryReturn` enum adapters,
`map_fs_errno`). The generated `uni_syscall.rs` refers to the universal types
through `crate::universal::...` paths, so it works unchanged as long as the
table above is followed.

## WIT pinning notes

- `uni-syscall.wit` declaration order **is** the wire `message_kind`
  numbering (1–23). Never reorder it.
- `uni-scalar.wit` discriminants are the deployed wire values: `u128` follows
  `u64`, `i128` follows `i64`, and the last case is `timestamp-tz`
  (PascalCase `TimestampTz`). `uni-scalar-value.wit` uses the same case names.
- `uni-data-type.wit` ends with `%box(box<uni-data-type>)` (wire tag 8,
  **after** `binary` at tag 7). The `Box` variant doubles as `mudu_gen`'s
  internal IR for WIT `box<T>` types, so it must stay even though no syscall
  payload carries it.

## After regenerating

Run, from this crate's directory:

```sh
cargo test -p mudu_api_rust
cargo test -p mudu_api_rust --features mock-sqlite
cargo clippy -p mudu_api_rust --all-targets -- -D warnings
cargo clippy -p mudu_api_rust --all-targets --features mock-sqlite -- -D warnings
cargo fmt --check
```

`tests/golden_frames_test.rs` compares the codec byte-for-byte against the
shared 47-frame corpus
(`crates/db-kernel/testing/fixtures/golden/v1/syscall_payload_v1_all.bin`).
If regenerated code changes any frame byte, **stop** and reconcile the WIT or
the generator templates instead of updating the corpus or the unit-test
snapshots — unless the wire format is being revised on purpose, in which
case regenerate the corpus once on the host side (see the host
`REGENERATE.md`).
