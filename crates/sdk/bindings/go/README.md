# mududb Go bindings

Go bindings for the mududb MSSP wire protocol: the hand-written MessagePack
and MSSP frame runtime (`codec`), the mgen-generated Uni* types and syscall
codecs (`types`), and the cross-language golden-corpus verification suite
(`corpus`).

The bindings ship pure Go artifacts only (no Rust sources), are
TinyGo-compatible (no `unsafe`, no generics, no reflection), and use only
the Go standard library.

## Layout

```
go.mod        module github.com/ybbh/mududb_p/bindings/go
codec/        hand-written runtime (package codec)
  mpack.go      canonical MessagePack writer / lenient reader, value model
  frame.go      MSSP v1 16-byte header + request/result body helpers
types/        package types
  wire.go       hand-written checked wire conversions (no "Generated" header)
  Uni*.go       mgen-generated Uni* types and MSSP func codecs
corpus/       golden-corpus go test suite (package corpus)
```

Files carrying the header `// Generated by mudu_gen. Do not edit manually.`
are produced by mgen from the single source of truth
`crates/common/mudu_binding/wit/` (23 × `uni-*.wit`) and regenerated with:

```sh
mgen message -i crates/common/mudu_binding/wit \
    -o crates/sdk/bindings/go/types -l go --with-func-codec
```

Everything else (this README, `go.mod`, `codec/`, `types/wire.go`,
`corpus/`) is hand-written.

## The wire model

Every generated record/variant/enum type converts through an exported
`XxxToValue` / `XxxFromValue` pair whose wire form rides on native Go
values (`nil` / `bool` / integer widths / `float64` / `string` / `[]byte` /
`[]any` / `map[uint64]any`); the generic `codec.MpackWriter.WriteValue` /
`codec.MpackReader.ReadValue` serialize that value model canonically
(byte-exact with the Rust host's rmp_serde output: minimal-width integers,
str8 for 32..=255, map keys ascending).

Wire rules pinned by the golden corpus:

- Records and request argument lists are integer-keyed MessagePack maps of
  the 1-based field/parameter numbers (WIT declaration order); option
  fields are omitted when nil (proto3 presence semantics).
- Variants are `[tag, payload]` 2-element arrays; payload-less cases carry
  a `0u8` placeholder.
- Results are `[0, value]` / `[1, error]`; unit results use `[0, 0]`.
- `list<u8>`/`blob` encodes as a MessagePack **bin** in func signatures but
  as an **array of u8** inside records/variants; decode is lenient and
  accepts both forms everywhere.
- Decode is lenient: any integer width is accepted (range-checked), unknown
  map keys are skipped, and missing fields/params decode as their
  proto3-style default (a missing variant field decodes as the first case
  with its zero payload).

Go surface notes:

- Variants are sealed interfaces (`UniDataType` with the unexported
  `uniDataTypeKind()` method) with one exported struct per case
  (`UniDataTypeScalar{Inner UniScalar}`, ...); enums are `uint32` const
  blocks.
- `option<T>` is `*T`; tuples travel as `[]any` carrying the typed element
  values (Go has no tuple type).
- `WireResult{Value any, Error *UniError}` carries result payloads; option
  ok payloads travel unwrapped (nil means absent).
- All generated codec functions return errors instead of panicking.

## Verification

The `corpus` package runs the cross-language golden corpus
(`crates/db-kernel/testing/fixtures/golden/v1/`) natively:

```sh
go test ./...
```

- `mp_primitives_v1` (44 vectors): canonical encoder byte-exactness and
  lenient decode of the primitive MessagePack shapes.
- `syscall_payload_v1_all` (47 frames): header routing, byte-exact request
  and ok/err response encodes, sidecar-`expect` decode equality, and
  decode → re-encode byte-identical roundtrips.
- `lenient_decode_v1` (8 vectors): non-canonical frames (widened integer
  markers, reordered/unknown/non-integer map keys, missing params/fields)
  decode to the same semantic expectations.

`go build ./...`, `go vet ./...` and `gofmt -l .` are all clean.
