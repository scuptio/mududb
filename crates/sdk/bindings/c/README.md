# mududb C binding

C99 (and C++17) binding for the mududb `uni-*` message surface: the WIT
message types as C structs plus their MessagePack codecs, and the MSSP v1
syscall frame/request/result codecs. The single source of truth is
`crates/common/mudu_binding/wit/` (23 × `uni-*.wit`); everything under
`mududb/types/` is generated by mgen and regenerated in the same commit when
the WIT changes.

## Layout

```
mududb/
  codec/
    mpack.h            hand-written MessagePack runtime + decode arena (the "mududb.codec" segment)
    mpack.c
    mpack_alloc.c      default libc-backed mp_realloc; replace to retarget allocation
    record_bridge.h    record bridge: uni-data-value record envelope <-> generated record codec map
    record_bridge.c
  types/
    UniOid.h           generated type + codec headers, one per WIT file ("mududb.types")
    ...
    UniSyscall.h       MSSP message kinds, frame helpers, per-syscall request/result codecs
tests/
  corpus_driver.c  golden-corpus conformance driver (native, libc/POSIX)
  mini_json.{h,c}  minimal JSON DOM for the sidecar files (test-only)
Makefile           native build + test targets
```

Every public header is self-contained: `#include "mududb/types/UniSyscall.h"`
with the package directory on the include path (`-I crates/sdk/bindings/c`)
pulls in everything it needs. Functions are `MP_INLINE` — `static inline`
in C, plain `inline` in C++ — so headers work in any translation unit
without link collisions, and every header is wrapped in `extern "C"` for
C++ users. There is no mutable global state.

## Ownership conventions (the contract that matters)

The binding never hides allocation behind your back; all memory comes from
explicit, caller-visible places:

- **Encode borrows.** `uni_*_encode(w, &value)` and the
  `uni_syscall_*_request_encode` / `*_result_encode` functions only *read*
  the values you pass. Strings/blobs are byte slices (`mp_str`/`mp_bin`);
  they may point at any memory that outlives the call.
- **The writer owns its buffer.** `mp_writer` grows its buffer through the
  `mp_realloc` hook (default: libc, in `mududb/codec/mpack_alloc.c`).
  `mpw_init`/`mpw_free` bracket the lifecycle; after a successful encode
  the frame is `w.buf`/`w.len` — send it, then `mpw_free(&w)`.
- **Decode never points into the input.** Every string, blob, array and
  boxed value a decoder produces is *copied* into a caller-provided
  `mp_arena` (`mpa_init` … `mpa_free`). Decoded strings are additionally
  NUL-terminated for convenience (`len` excludes the terminator). The
  input buffer may be reused or freed as soon as decode returns.
- **One arena, one free.** There are no per-type `free` functions and
  nothing is individually owned: release everything a decode produced
  with a single `mpa_free(&a)`. Arena allocations are 8-byte aligned and
  bump-allocated, so decode is a sequence of pointer bumps.
- **Failures are sticky.** Writers flag allocation failures and invalid
  values (`mpw_fail`, e.g. an unknown variant tag); readers flag
  malformed input (`mpr_ok`/`mpr_fail`). Decode functions return 0/-1 and
  partially written outputs are discarded by the caller — check the
  return value before using `out`.

Thread-safety follows from the contract: a `mp_writer`/`mp_reader`/
`mp_arena` triple is independent per call, so concurrent encodes/decodes
on separate triples need no locking.

## Record bridge (user-defined record types)

A procedure parameter of a project record type (declared in the project's
own `types.wit`, generated with `mgen message -l c`) travels the byte pipe
as the `uni-data-value` **record case**: field entries in WIT declaration
order, names possibly empty (the host drops them — positional semantics).
`mududb/codec/record_bridge.h` converts between that envelope and the
integer-keyed MessagePack map shape the generated `<type>_decode` /
`<type>_encode` codecs use, so a record argument decodes with two calls:

```c
mp_writer w;
mp_reader r;
mp_arena a;
profile p;
mpw_init(&w);
if (mp_record_bridge_write(record_envelope, &w) == 0) {  /* envelope -> map bytes */
    mpr_init(&r, w.buf, w.len);
    mpa_init(&a);
    profile_decode(&r, &a, &p);                          /* generated codec */
}
```

and a record return value encodes symmetrically (`profile_encode` renders
the map, `mp_record_bridge_read` wraps it back into the record-case
envelope the host expects). The bridge header documents the exact wire
rules — positional keys, bool fields crossing as i32 0/1 both directions
(`mpr_bool` accepts integer markers 0/1 for exactly this reason), nil for
omitted trailing `option` fields, gap-filled middle omissions, and the
host's transactable scalar vocabulary on the read side. Ownership follows
the contract above: the write side borrows, the read side copies into the
caller's arena.

## Type mapping (WIT → C)

| WIT | C |
|---|---|
| `bool` | `bool` |
| `u8`/`u16`/`u32`/`u64` | `uint8_t`/`uint16_t`/`uint32_t`/`uint64_t` |
| `s8`/`s16`/`s32`/`s64` | `int8_t`/`int16_t`/`int32_t`/`int64_t` |
| `f32`/`f64` | `float`/`double` |
| `char` | `char` (wire: 1-byte string) |
| `string`/`numeric`/`date`/`time`/`timestamp`/`timestamp-tz` | `mp_str` byte slice |
| `list<u8>` (`blob`) | `mp_bin` byte slice |
| `list<T>` | generated `{ T *items; uint32_t len; }` slice struct |
| `option<T>` (record field) | value field + `bool <name>_is_null` flag (omitted from the wire map when null) |
| `option<T>` (elsewhere) | generated `{ int has_value; T value; }` wrapper |
| `box<T>` | `T *` (arena-owned on decode) |
| `tuple<A, B, …>` | generated `{ … f0; … f1; }` struct |
| `enum` | C enum (`UNI_SCALAR_U8` …) |
| `record` | `struct` (fields snake_case; `option` fields get the flag) |
| `variant` | `<type>_kind` tag enum + struct with a `kind` tag and an `as.<case>` union |

Two representation rules worth knowing:

- **Variant payloads of named record/variant types are pointers**
  (`uni_data_type *array;` rather than a by-value member). Arena-owned on
  decode (allocated through the generated `<T>_decode_new`), borrowed on
  encode; a null payload pointer on encode flags the writer instead of
  emitting a corrupt frame. This keeps every cross-file type reference
  pointer-sized, which is what makes the per-file self-contained headers
  acyclic. Enum payloads and scalar/string/blob payloads stay by value.
- **`list<u8>` has the pinned dual semantics**: inside records/variants it
  is a MessagePack ARRAY of `u8` (matching the Rust host's `Vec<u8>` serde
  output); at func signature level it is a MessagePack **bin** blob. The
  generated codecs pin this exactly.

## Wire shapes (MSSP v1)

- Frames: 16-byte header (`magic "MSSP" | version 1 | flags 0 |
  message_kind`, all big-endian) + one MessagePack body.
- Records and request argument lists are MessagePack **maps** keyed by the
  1-based field/parameter numbers (WIT declaration order).
- Variants are `[tag, payload]` 2-arrays; payload-less cases carry a `0u8`
  placeholder (NOT nil). Results are `[0, value]` / `[1, UniError]`.
- Encoders are canonical (shortest integer/str form, matching rmp_serde);
  decoders are lenient (integer keys of any width, unknown keys skipped,
  missing fields/params defaulted).

## Using it

```c
#include "mududb/codec/mpack.h"
#include "mududb/types/UniSyscall.h"

/* encode a `get` request frame (key = "k1") */
mp_writer w;
uni_oid oid = {0, 6};
static const uint8_t key[] = {'k', '1'};
mpw_init(&w);
if (uni_syscall_get_request_encode(&w, &oid, mp_bin_from(key, 2)) == 0) {
    /* send(w.buf, w.len) */
}
mpw_free(&w);
```

```c
/* decode a `get` result frame */
mp_reader r;
mp_arena a;
uni_syscall_get_result res;
mpr_init(&r, frame, frame_len);
mpa_init(&a);
if (uni_syscall_get_result_decode(&r, &a, &res) == 0 && !res.is_err
        && res.value.has_value) {
    /* res.value.value is an mp_bin living in the arena */
}
mpa_free(&a);
```

To retarget allocation (static pools, logging allocators, …), replace
`mududb/codec/mpack_alloc.c` — `mp_realloc(old, old_size, new_size)`
allocates when `old` is null, frees when `new_size` is 0.

## Tests

```
make test      # build + run the golden-corpus driver (398 checks)
make test-c    # every public header compiles standalone as C99
make test-cpp  # every public header and the runtime compile as C++17
make check     # all of the above
```

The driver walks up from the current directory to find
`crates/db-kernel/testing/fixtures/golden/v1/` (the
`crates/sdk/bindings/python/corpus_common.py` pattern) and runs three
suites against the cross-language fixtures: `mp_primitives_v1` (canonical
encoder byte-exactness vs rmp_serde goldens), `syscall_payload_v1_all`
(47 frames: byte-exact request/response encodes, decode-vs-sidecar
semantic equality, decode→re-encode roundtrips), and `lenient_decode_v1`
(8 non-canonical vectors).

## Regeneration

The generated headers are refreshed with mgen (do not hand-edit them —
every file starts with `// Generated by mudu_gen. Do not edit manually.`):

```
cd crates/tools && cargo build -p mudu_gen --bin mgen
target/debug/mgen message -i crates/common/mudu_binding/wit \
    -o crates/sdk/bindings/c/mududb/types -l c --with-func-codec
```

`script/ci/check_bindings_regen.sh` gates that the checked-in files are
byte-identical to a fresh regen.
